# UFC Fight Predictor

A complete machine‑learning pipeline that predicts the winner of a UFC fight using historical fighter statistics. The model is deployed as a REST API and integrated into a personal portfolio website.

> **Live demo:** [danielscottbaker.com/ufc-predictor](https://danielscottbaker.com/ufc-predictor)

---

## Project Overview

- **Data source**: Kaggle UFC dataset (scraped from UFCStats.com)
- **Features**: 40 engineered attributes including physical stats (height, weight, reach), career averages, recent 3‑fight rolling windows, and head‑to‑head difference features
- **Model**: XGBoost with extensive hyperparameter tuning (randomised search over 500 candidates)
- **Validation**: Time‑series cross‑validation (5 folds, chronologically ordered)
- **Best Log Loss**: 0.6311
- **Training samples**: 6,015 fights (after removing draws/no‑contests)
- **Deployment**: Flask API on Render, auto‑deploy on push

## Setup (Local)

### 1. Clone the repository

```bash
git clone https://github.com/<your-username>/ufc-predictions.git
cd ufc-predictions
```

### 2. Create & activate the project‑specific virtual environment

```bash
python3 -m venv ufc-venv
source ufc-venv/bin/activate
```

### 3. Install dependencies

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

*Note: On macOS you may need to install OpenMP for XGBoost:*  
`brew install libomp`

### 4. Download the dataset

```bash
python -m src.ingestion
```

This will place the raw CSV files into `data/raw/`.

### 5. Run the full pipeline

```bash
python -m src.preprocessing   # Cleans data, engineers features, saves to ufc.db
python -m src.train           # Tunes and trains the XGBoost model → models/ufc_model.pkl
```

### 6. Test a prediction

```bash
python src/predict.py "Jon Jones" "Stipe Miocic"
```

## Data Pipeline

```
Raw UFC CSVs
    │
    ├─ ingestion.py  (KaggleHub download)
    │
    ├─ preprocessing.py
    │   ├─ Clean fighter details (height → inches, weight → float, percentages)
    │   ├─ Build historical features
    │   │   ├─ Expanding career averages (all past fights)
    │   │   ├─ Rolling 3‑fight averages (current form)
    │   │   └─ Fight count before each bout
    │   ├─ Merge static physical attributes
    │   ├─ Create target (1 if Red corner won, 0 if Blue)
    │   ├─ Add difference features (Red stat – Blue stat)
    │   └─ Save to SQLite database (fight_features, fighter_current_features)
    │
    └─ train.py
        ├─ Safe time‑series cross‑validation (skips single‑class folds)
        ├─ Randomised hyperparameter search (XGBoost)
        ├─ Retrains best model on all data
        └─ Saves model to models/ufc_model.pkl
```

## Model Performance

- **Algorithm**: XGBoost
- **Features**: 40 (static + historical + differences)
- **Best hyperparameters** (found via random search over 500 candidates):
  - `n_estimators=300`, `learning_rate=0.01`, `max_depth=10`
  - `subsample=0.9`, `colsample_bytree=0.8`
  - `reg_alpha=0.1`, `reg_lambda=0`, `gamma=0.1`, `min_child_weight=5`
- **Cross‑validation log loss**: 0.6311 (baseline random guess ≈ 0.69)
- **Train‑test splits**: Chronological, ensuring no future data leakage

## API Deployment

The Flask API is deployed on **Render**. The server runs `api.py` using `gunicorn`.  
On every push to the `main` branch, Render automatically rebuilds and deploys.

**Endpoints:**
- `POST /predict` – Expects JSON: `{"fighter_a": "Name", "fighter_b": "Name"}`  
  Returns: `{"fighter_a": "...", "fighter_b": "...", "probability_red_wins": 0.81}`

**Cold start**: The free tier idles after 15 minutes of inactivity. The first request may take up to 40 seconds while the server boots.

## Automated Weekly Updates

A **GitHub Actions** workflow (`weekly_update.yml`) runs every Sunday at midnight UTC. It:

1. Checks out the repository
2. Installs Python dependencies
3. Downloads the latest Kaggle dataset
4. Re‑runs preprocessing and model training
5. Commits & pushes the updated `ufc.db` and `models/ufc_model.pkl`

**Secrets required:**  
Add `KAGGLE_USERNAME` and `KAGGLE_KEY` to your repository’s **Settings → Secrets → Actions**.

The workflow can also be triggered manually from the Actions tab.

## Usage

### Command line

```bash
python src/predict.py "Jon Jones" "Stipe Miocic"
# Probability that Jon Jones (Red corner) wins: 81.05%
```

### HTTP API

```bash
curl -X POST https://ufc-predict-api.onrender.com/predict \
  -H "Content-Type: application/json" \
  -d '{"fighter_a":"Jon Jones","fighter_b":"Stipe Miocic"}'
```

### JavaScript (frontend)

```javascript
const response = await fetch('https://ufc-predict-api.onrender.com/predict', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ fighter_a: 'Jon Jones', fighter_b: 'Stipe Miocic' })
});
const data = await response.json();
console.log(`${data.fighter_a} wins: ${(data.probability_red_wins * 100).toFixed(1)}%`);
```
